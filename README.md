# ShieldCore 污点约束检测规则库

对已经解码的请求文本做规则匹配与证据定位。调用方提供文本与不可信来源
对应的污点区间；本库只负责"哪条规则命中、证据在哪"，不实现探针、攻击
分类或拦截动作。

## 使用

```go
rs, err := shieldcore.Compile([]byte(`[
  {"id": "rule-1", "pattern": "(a|aa)*b"},
  {"id": "rule-2", "pattern": "x[a-c]+y"}
]`))
if err != nil { /* 规则非法：超 500 条、pattern 超 256 字节、id 重复、语法错误 */ }

ev, err := rs.Scan("xxabcyy", []shieldcore.Span{{Start: 3, End: 5}})
// ev == []shieldcore.Evidence{{ID: "rule-2", Start: 1, End: 6}}
```

- `Compile` 接收 JSON 规则数组（`[{"id":..., "pattern":...}]`），返回可重复
  使用的 `*Ruleset`。最多 500 条规则，每个 pattern 最多 256 字节，id 必须唯一。
- `Scan` 接收规则集、ASCII 文本、按起点递增且互不重叠的非空污点区间
  （半开字节区间，从零开始），按规则输入顺序返回每条命中规则的一条证据。

## 正则语法

ASCII 字面量、元字符字面转义（`\*`、`\.` 等）、点号 `.`（匹配任意 ASCII
字节，含换行）、字符类及范围和取反（`[a-c]`、`[^ab]`）、圆括号分组、交替
`|`、量词 `*` `+` `?`。不支持锚点、预定义字符类、计数量词、捕获与环视。

## 命中与证据选择规则

规则命中，当且仅当存在一个被其正则**完整接受**的**非空**子串，且该子串与
至少一个污点区间有非空交集。每条命中规则只返回一条证据：所有合格子串中
起点最小者，起点相同时终点最大者。交替分支书写顺序不影响结果；空匹配不
构成证据；没有污点区间时任何规则都不命中。

注意这不是"先常规匹配再过滤污点"：`pattern=aba`、`text=ababa`、污点
`[4,5)` 必须返回 `[2,5)`，而不是因为先找到的 `[0,3)` 无污点而漏报。

## 实现与复杂度

令 N 为文本字节数，T 为污点区间数，S 为全部 pattern 字节数加规则数。

- 每条 pattern 经 Thompson 构造编译为 NFA，全部规则共享一个前向自动机和
  一个反向自动机（所有边反转），状态总数 O(S)。编译时对 epsilon 图做
  Tarjan SCC 分解并按凝聚图拓扑序保存，因此每个位置的 epsilon 闭包是
  严格的 O(S) 松弛，不存在反复传播。
- **前向扫描**：每个位置把全局起点以"当前位置"为种子注入（即匹配可在任意
  位置开始），逐状态维护可达的**最小起点**。位置 j 处接受态的值即为"以 j
  结尾的接受子串的最小起点"i——若同一终点存在更短起点的子串，它必然包含
  后者，故它与污点相交当且仅当该终点存在任一与污点相交的接受子串。用单调
  指针在有序污点区间上 O(1) 摊还判定相交，得到每条规则的最小合格起点 i*。
- **反向扫描**：在反转自动机上同理维护**最大终点**，当扫描位置经过 i* 时
  读出接受态的值，即为该起点的最大终点 j*。同起点更长的匹配必然包含更短
  的，故它同样与污点相交，选择合法。
- 一次 Scan 最坏时间 O((N+1)×S+T)（含不命中输入）；编译后常驻内存与扫描
  额外内存均为 O(S)：只有三个长度为状态数的切片（当前值、下一步种子、
  分量值），不复制输入文本，不建逐字节污点副本，不枚举子串，不逐起点
  重启匹配，高度重叠的匹配也只占有一份有界状态。

## 测试

```
go test ./...
```

- `shieldcore_test.go`：规定场景（重叠漏报回归、`a|aa` 选 `[0,2)`、可接受
  空串的模式、无污点不命中、点号匹配换行、字符类/转义/分组、结果顺序、
  编译与扫描入参校验）。
- `random_test.go`：固定随机种子生成短文本、规则与污点区间，与枚举所有
  子串的独立参考实现（基于标准库 `regexp`，不复用生产匹配逻辑）逐条比较
  命中与位置。
- `perf_test.go`：对 10 万 / 20 万 / 40 万个连续 `a` 分别运行 `(a|aa)*b`
  的失败匹配与 `a+` 的全污点成功匹配，断言成功场景只产生一条覆盖全文的
  证据，记录耗时与每次扫描的内存增长（本机实测：三种规模下每次扫描分配
  恒定约 672B / 320B，耗时比约 2.7–3.2 对应 4 倍输入，符合线性）。状态数
  只取决于 pattern，与 N 无关，这与实验共同支撑 O((N+1)×S+T) 的复杂度约束。
