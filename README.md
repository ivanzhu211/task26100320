# shieldcore

ShieldCore 污点约束检测规则库。调用方提供已解码的请求文本和不可信来源的污点区间，
本库只做规则匹配与证据定位，不含探针、攻击分类或拦截动作。

## 使用

```go
rules, err := shieldcore.Compile([]byte(`[
  {"id": "r1", "pattern": "aba"},
  {"id": "r2", "pattern": "(a|aa)*b"}
]`))
if err != nil { /* 规则非法：重复 id / 超限制 / 语法错误 */ }

ev := shieldcore.Scan(rules, "ababa", []shieldcore.Interval{{Start: 4, End: 5}})
// ev == []shieldcore.Evidence{{ID: "r1", Start: 2, End: 5}}
```

- `Compile` 接收 JSON 规则数组，返回可重复使用的 `*Ruleset`。
  最多 500 条规则，每条 pattern 最多 256 字节，id 必须唯一。
- `Scan` 接收规则集、ASCII 文本、按起点递增且互不重叠的非空污点区间，
  返回各命中规则的 id 与证据区间（零起始半开字节区间），按规则输入顺序排列。
- 每条规则至多返回一条证据：在所有“被正则完整接受且与至少一个污点区间相交”的
  非空子串中，取起点最小者，起点相同取终点最大者。空匹配不构成证据；
  没有污点区间时任何规则都不命中。

## 正则语法

ASCII 字面量、元字符字面转义（`\.`、`\*` 等）、`.`（匹配任意 ASCII 字节，含换行）、
字符类（`[a-c]`、`[^a-c]`、类内转义）、圆括号分组、交替 `|`、量词 `*` `+` `?`。
不支持锚点、预定义字符类、计数量词、捕获结果、回溯引用与环视。

## 实现与复杂度

- 编译：全部规则经 Thompson 构造合成一个组合 NFA，状态数与边数均为 O(S)
  （S = 全部 pattern 字节数 + 规则数）。对 epsilon 图做 Tarjan SCC 分解，
  消除 `*`/`+` 引入的 epsilon 环对闭包计算的影响。
- 扫描：对文本做一遍从左到右的 NFA 模拟。每个位置注入所有规则的起点（起点=i），
  每个 SCC 携带“能到达它的最小起点”；因为 NFA 转移与起点无关，较早起点支配较晚起点
  （更长的子串仍与同样的污点相交），所以每个状态只需保存一个最小起点，
  高度重叠的匹配也只占用有界状态。每个位置的工作 = 活跃状态及其转移各扫描一次
  = O(S)，总计 O((N+1)×S)。污点判定用一个随位置单调前进的指针，
  均摊 O(1)，总计 O(T)。不枚举子串、不收集全部匹配、不按起点重启匹配。
- 内存：编译产物 O(S)；扫描的 scratch 数组（状态/SCC 各一份，按位置复用、
  代际戳清零）在每次 Scan 开头一次性分配，同为 O(S)，逐位置零分配；
  不复制输入文本，不建立逐字节污点副本。
- 证据选择：每个结束位置 i 得到该规则的最小起点 L(i)。候选只需考虑 (L(i), i)：
  若最优合格子串为 (s*, i*)，则 (L(i*), i*) 起点不更晚、终点相同、且仍与同一污点相交，
  故受限集合上的最优即全局最优；交替分支书写顺序因此不影响结果。

## 测试

```
go test ./...                 # 全部测试（场景 + 随机差分 + 性能实验）
go test -run TestPerformance -v   # 仅性能实验，打印耗时/内存表
go test -bench . -benchmem        # 基准形式复测
```

覆盖内容：

- 规定场景：`aba`/`ababa`/污点 `[4,5)` 必须报 `[2,5)`（先找到的 `[0,3)` 无污点不能漏报）；
  `a|aa` 与 `aa|a` 在 `aa`、污点 `[0,1)` 下都必须选 `[0,2)`；可接受空串的模式
  （`a*`、`()`、`(ab)*`）只在存在非空匹配时报证据。
- 随机差分：固定种子 42 生成 3000 组短文本/规则/污点区间，与“枚举所有子串 +
  标准库 regexp 判定完整接受”的独立参考实现逐条比对命中与位置（参考实现仅用于测试）。
- 性能实验：对 10 万 / 20 万 / 40 万个连续 `a`，分别运行 `(a|aa)*b` 的失败匹配与
  `a+` 的全污点成功匹配。实测（本机，go1.27 darwin/arm64）：

  | N | 失败 `(a\|aa)*b` | 成功 `a+` | 扫描分配 |
  |--------|------|------|-------|
  | 100000 | ~10ms | ~3.5ms | 恒定 ~1KB 以下 |
  | 200000 | ~20ms | ~6.6ms | 同上 |
  | 400000 | ~40ms | ~13ms | 同上 |

  成功场景只产生一条覆盖全文的证据 `[0,N)`。耗时随 N 严格线性（每翻倍规模耗时约翻倍），
  而扫描分配不随 N 增长——这与代码结构相互印证：每个位置只扫描有界的 NFA 状态集（O(S)），
  所有 scratch 缓冲按位置复用，污点指针单调前进，因此最坏时间 O((N+1)×S+T)、
  额外内存 O(S)。
